# Описание Excel-спецификации и основа для цифровизации

## 1. Назначение документа

Данный Excel-документ представляет собой производственно-коммерческую спецификацию заказа.
Форма используется для оформления заказа, фиксации параметров изделия, расчёта площади, стоимости, предоплаты, остатка, статуса производства и ключевых дат.

Пример из документа:

- Номер спецификации: `124/05`
- Дата оформления: `2026-01-23`
- Тип заказчика: `ИП`
- Заказчик: `Баранов`
- Статус: `В производстве`
- Дата передачи в производство: `2026-01-26`
- Дата готовности: `2026-02-16`
- Предоплата: `25000`
- Остаток: `11229.27065`
- Итого: `36229.27065`

## 2. Структура текущего Excel-документа

Файл содержит минимум два смысловых листа.

### 2.1. Лист `СПЕЦИФИКАЦИЯ`

Основная печатная форма заказа.

Содержит:

- шапку документа;
- номер и дату спецификации;
- данные заказчика;
- юридический тип заказчика;
- производственный статус;
- даты производства, готовности и отгрузки;
- параметры заказа;
- сгруппированную таблицу позиций;
- расчёт площади и стоимости;
- блок оплаты;
- подписи исполнителя и заказчика.

### 2.2. Лист `Лист1`

Справочный лист.

Содержит справочники для заполнения спецификации:

- категории;
- типы покрытия / материала;
- толщины;
- виды фрезеровки;
- типы юридических лиц.

Примеры справочных значений:

- Категории: `покраска`, `ПВХ`, `шпон`
- Типы: `мат/лам`, `мат/мат`, `глянец/лам`, `глянец/мат`, `глянец/глянец`
- Толщины: `10`, `16`, `19`, `22`, `25`, `32`, `38`
- Фрезеровка: `R 3`, `R минимальный`, `Альфа`, `Ампир`, `Антик`, `без R`, `Версаль`, `Дрезден`, `Лондон`, `Неаполь`
- Типы лиц: `ООО`, `ИП`, `ч/л`, `ЗАО`

## 6. Табличная часть спецификации

Табличная часть спецификации не является простым списком одинаковых товарных позиций.
Внутри неё могут находиться разные типы строк:

- строка-группа / заголовок группы;
- товарная позиция;
- услуга или дополнительная операция;
- комментарий;
- пустая техническая строка;
- итоговая или расчётная строка.

Поэтому вместо простой сущности `OrderItem` рекомендуется использовать универсальную сущность `SpecificationLine`.

## 7. Сущность `SpecificationLine`

| Поле | Тип | Обязательное | Описание |
|---|---:|---:|---|
| `id` | UUID | Да | Идентификатор строки |
| `order_id` | UUID | Да | Ссылка на заказ / спецификацию |
| `parent_id` | UUID / null | Нет | Ссылка на родительскую группу |
| `line_type` | Enum | Да | Тип строки |
| `sort_order` | Integer | Да | Порядок отображения |
| `title` | String | Нет | Название строки или группы |
| `description` | Text | Нет | Описание / примечание |
| `height_mm` | Decimal(10, 2) | Нет | Высота изделия |
| `width_mm` | Decimal(10, 2) | Нет | Ширина изделия |
| `quantity` | Decimal(10, 3) | Нет | Количество |
| `unit` | String | Нет | Единица измерения: `шт`, `м²`, `м.п.`, `усл.` |
| `price_per_m2` | Decimal(12, 2) | Нет | Цена за м² |
| `unit_area_m2` | Decimal(12, 6) | Нет | Площадь одной единицы |
| `total_area_m2` | Decimal(12, 6) | Нет | Общая площадь строки |
| `unit_price` | Decimal(12, 2) | Нет | Стоимость одной единицы |
| `total_price` | Decimal(12, 2) | Нет | Общая стоимость строки |
| `is_calculated` | Boolean | Да | Участвует ли строка в расчётах |
| `is_printed` | Boolean | Да | Отображается ли строка в печатной форме |
| `metadata` | JSONB | Нет | Дополнительные параметры строки |

### 7.1. Возможные значения `line_type`

| Значение | Описание | Участвует в расчётах |
|---|---|---:|
| `group` | Название группы / раздела внутри спецификации | Нет |
| `product` | Основная товарная позиция с размерами, количеством и ценой | Да |
| `service` | Услуга или операция, например присадка | Да |
| `comment` | Комментарий или пояснение внутри таблицы | Нет |
| `empty` | Пустая строка для визуального разделения | Нет |
| `subtotal` | Промежуточный итог по группе | Да / Нет |
| `total` | Итоговая строка всей спецификации | Да |
| `discount` | Скидка | Да |
| `surcharge` | Наценка / дополнительная сумма | Да |

### 7.2. Пример группировки строк

```text
Группа: Фасады верхние
  Позиция: 1190 x 348, 6 шт.
  Позиция: 1190 x 305, 1 шт.
  Услуга: присадки, 24 шт.

Группа: Фасады нижние
  Позиция: ...
  Позиция: ...
```

В базе данных это может храниться так:

| id | parent_id | line_type | title | sort_order |
|---|---|---|---|---:|
| `1` | null | `group` | `Фасады верхние` | 10 |
| `2` | `1` | `product` | null | 20 |
| `3` | `1` | `product` | null | 30 |
| `4` | `1` | `service` | `присадки` | 40 |
| `5` | null | `group` | `Фасады нижние` | 50 |

### 7.3. Примеры строк

| Высота | Ширина | Кол-во | Примечание | Цена за м² | Площадь 1 ед. | Общая площадь | Сумма |
|---:|---:|---:|---|---:|---:|---:|---:|
| 1190 | 348 | 6 | 4 прис. по 1190 | 13500 | 0.41412 | 2.48472 | 33543.72 |
| 1190 | 305 | 1 | 16мм, без R | 8300 | 0.36295 | 0.36295 | 3012.49 |
| — | — | 24 | присадки | 100 | 0 | 0 | 2400 |

## 8. Расчётные поля

Часть полей должна рассчитываться автоматически.

### 8.1. Площадь одной товарной позиции

```text
unit_area_m2 = height_mm * width_mm / 1_000_000
```

### 8.2. Общая площадь позиции

```text
total_area_m2 = unit_area_m2 * quantity
```

### 8.3. Стоимость одной единицы

```text
unit_price = unit_area_m2 * price_per_m2
```

### 8.4. Общая стоимость товарной позиции

```text
total_price = unit_price * quantity
```

### 8.5. Стоимость услуги

```text
total_price = quantity * unit_price
```

### 8.6. Итог по группе

```text
group_total = sum(child_lines.total_price where child_lines.is_calculated = true)
group_area = sum(child_lines.total_area_m2 where child_lines.is_calculated = true)
```

### 8.7. Итог заказа

```text
total_amount = sum(specification_lines.total_price where is_calculated = true)
```

### 8.8. Остаток

```text
balance_amount = total_amount - sum(payments.amount)
```

Важно: строки типа `group`, `comment` и `empty` не должны попадать в финансовые и площадные итоги.

## 14. Импорт из Excel/XML

Для переходного периода можно реализовать импорт старых спецификаций.

Рекомендуемый процесс:

1. Загрузка Excel/XML-файла.
2. Парсинг листа `СПЕЦИФИКАЦИЯ`.
3. Извлечение шапки документа.
4. Извлечение строк заказа.
5. Определение типов строк: группа, товар, услуга, комментарий, итог.
6. Извлечение итогов.
7. Сопоставление значений со справочниками.
8. Проверка пользователем.
9. Сохранение в базу данных.
10. Генерация новой цифровой спецификации.

## 15. Валидации

Рекомендуемые проверки:

- номер спецификации обязателен и уникален;
- дата оформления обязательна;
- заказчик обязателен;
- количество должно быть больше нуля для расчётных строк;
- ширина и высота должны быть больше нуля для товарных позиций;
- цена за м² должна быть неотрицательной;
- итоговая сумма не может быть отрицательной;
- дата готовности не должна быть раньше даты оформления;
- дата отгрузки не должна быть раньше даты оформления;
- остаток должен пересчитываться автоматически;
- строка-группа не должна участвовать в расчётах;
- строка-комментарий не должна участвовать в расчётах;
- удаление справочников должно быть мягким через `is_active = false`.
